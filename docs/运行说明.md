# 运行说明

最近一次可用修订：2026-10-10，提交以 Git `main` 为准。下面是已经定下来的行为。改完并确认可用后，把变化补进这一节，不要只留在对话里。

## 没有热备

热备是第二条已经拨通的隧道，网卡和进程会一直占着。512MB 机器会因此进交换，网卡还在但对端不回包时，8500 也会一直超时。

热备拨号代码已删除，不会再启动。备用只有：

- 1 条主连接：唯一已经拨通、正在转发的隧道。
- 1 条冷备：只做端口检查，不建隧道。
- 最多 5 条预冷备：同样只做端口检查。

冷备大约每 60 秒查一次端口。主连接掉了，先接冷备，再从预冷备里补上冷备。

## 主连接什么时候算坏

进程在、网卡在，不够。经这条隧道打不开网页，就是不转发。

- 刚连上时先确认能转发，再测速。不转发就拆掉，换下一个。
- 已经连着的隧道每 60 秒查一次。连续两次不转发，拆掉这条，这个地址 30 分钟内不再当冷备或预冷备，然后改接冷备。
- 测速低于当前门槛（默认 10 Mbps，可选 5、10、20、30、50、80、100）就标不稳定，换下一个。列表里这种节点显示为不可用，不显示为可用。
- 管理页上「主连接」是绿色表示客户端出口可用。红色只表示客户端出口不可用。节点库里旧的检测状态不再把一条正在用的主连接涂红。
- 一次测速没有结果，或者端口探测留下的旧速度，不能把节点改成不可用。只有这次测速确实低于门槛，才标不可用。端口能通、客户端能连上的节点保持可用。
- 刚测通过的隧道，10 分钟内不因为一次网页超时就拆掉。连续三次确认不转发，才改走冷备。


## 切换顺序

手动操作优先于自动切换：直连/代理按钮、列表里的「切换」、代理设置点保存。自动切换要等这些做完。

- 直连改代理：当前隧道必须能转发，已测速度为 0 或者不低于门槛。不够就排除这个地址，先断开，再连下一个，然后把 8500 指到新隧道。
- 代理改直连：先把 8500 改回服务器自己的网卡，再撤回隧道路由。
- 列表点另一个节点：OpenVPN 只有 `tun0`，先断开旧的再连新的。其它协议有自己的网卡时，先建新的再拆旧的。

## 列表里的检测

「待检测」和「不可用」都可以点。先查端口：TCP 看端口是否开放，UDP 看有没有协议应答。端口不通就写入不可用，不再测速。端口通了再测速，速度写进节点库并显示在列表里。不访问网页来判断节点好坏。

点「收藏」只改收藏名单，不抢连接用的锁。8 秒没有返回就恢复按钮，不会停在「收藏中」。
