# 开发说明

## 仓库

同一份代码推到两个 GitHub 仓库的 `main`：

- `hankinsus/aimili-vpngate-production`
- `ilovestudyus-sketch/aimili-vpngate-ilovestudy`

运行中的管理机从第一个仓库拉取。功能改动之后，两个仓库和两台机器的提交号必须相同。只改文档时只推仓库，不重启服务。

## 代码在哪

| 文件 | 作用 |
|---|---|
| `vpngate_manager.py` | 管理页、连接、切换、检测、冷备 |
| `node_pool.py` | 节点库。列表和状态以这里为准 |
| `proxy_server.py` | 本机转发口。代理模式绑隧道，直连模式绑服务器网卡 |
| `tunnel_adapters.py` | OpenVPN 以外的协议 |

节点列表读节点库的一页，不把全库装进管理进程。OpenVPN 配置正文在单独文件里，`nodes.json` 只作配置缓存。

## 不能再出现的问题

列表接口里用到的锁和缓存，必须在模块加载时就存在。缺名字会让该请求不返回内容，前面的网页服务器就显示 502。

判断节点不可用，只能依据这一次的端口或测速结果。旧的速度数字、测速没返回，都不能改状态。

热备拨号函数保留为空返回，避免旧调用再拉起第二条隧道。不要把它们接回启动流程。
