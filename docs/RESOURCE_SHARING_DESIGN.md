# AimiliVPN Resource Sharing Design v1

## 目标

让多台 AimiliVPN 服务器之间共享节点资源信息，使每台服务器的资源池能够随运行时间和可信 Peer 数量增长，同时不直接共享账号密码、VPN 隧道凭据或本机管理权限。

## 网络与端口

不新增公网端口，继续使用现有 8443 HTTPS 管理入口。

资源同步接口建议：
- HTTPS 8443
- 独立 API 路径：/api/resource-share/*
- Peer 只能访问资源同步接口，不能访问管理页面、连接控制、代理设置等管理员 API。

## Peer 建立

### 1. 管理员创建邀请码

邀请码：
- 单次使用
- 默认 30 分钟过期
- 可撤销
- 不包含服务器密码
- 只用于首次建立 Peer 信任

### 2. 对方服务器输入邀请码

双方交换：
- peer_id
- Ed25519 公钥
- 服务端身份指纹
- 资源共享范围
- 同步方向

邀请码验证完成后，双方保存 Peer 公钥和身份，不再长期使用邀请码。

## 访问控制

管理员可配置：
- 允许的 Peer IP/CIDR
- Peer HTTPS 端口
- Peer 同步方向：只读 / 只写 / 双向
- 单个 Peer 最大节点数量
- 同步周期
- 共享协议范围：OpenVPN / SoftEther / SSTP / L2TP-IPsec

IP/CIDR 是第一层网络限制；Peer 公钥签名是第二层身份认证。

## 节点合并

共享节点进入本地 Master Node Pool，但标记：
- source=shared
- peer_id
- shared_at
- source_peer_count

唯一键仍使用：
- server_key
- protocol
- transport
- port

重复资源不重复创建。

## 信任规则

来自 Peer 的节点默认不能直接进入 HOT。

流程：
共享节点
→ 写入本地资源库
→ 本机检测
→ 通过后 AVAILABLE
→ 连续稳定后 HOT

这样失效的共享资源不会直接污染本机 Hot Pool。

## 双向共享

A 与 B 建立双向 Peer 后：

A 的新资源 → B  
B 的新资源 → A

只同步资源信息和检测结果摘要，不同步：
- 管理账号
- 管理密码
- SOCKS5 密码
- Web 登录安全后缀
- VPN 认证私密信息

## 资源池长期增长

本地数据库保留 first_seen / last_seen / source / protocol / probe history。

节点暂时消失：
- 不立即删除
- 降为历史资源
- 后续重新出现自动恢复

因此服务器运行时间越长，历史资源画像越完整。

## 国家平衡

资源调度采用：
1. 每个国家优先维护最低库存 20 个唯一 IP。
2. 每个国家优先维护 5 个以上可用 IP，目标 8 个。
3. 国家库存未达到目标时优先采集该国家。
4. 国家库存达到目标后进入全球补充池。
5. 日本、韩国等资源较多国家可以补充全球池，但不能长期占用全部采集预算。
6. 只有其它国家已经跨来源确认无足够新资源时，才允许富余国家大量扩大全球池。
7. “20 IP / 5-8 可用”是目标，不伪造数量；资源不足时保留真实数量。

## 邀请码撤销

管理员可以：
- 立即暂停 Peer
- 删除 Peer
- 重新生成邀请码
- 清理该 Peer 提供的共享节点
- 保留本机已经验证成功的节点

## 审计

记录：
- Peer 建立时间
- 最后同步时间
- 新增节点数量
- 去重数量
- 本机验证通过数量
- Peer 删除/暂停记录

不记录邀请码明文到普通日志。
